# Обновление расписания

Используй навык после добавления календаря, при наступлении выбранного срока проверки, переносе событий и когда агент заметил просроченную проверку. Найди соответствующий личный навык `local-*` по имени из будильника или описанию источника и прочитай его: там ссылка на календарь, фильтры, частота и особенности. Python-приложение календарь не запрашивает.

1. Прочитай `data/agent-state.json`, затем фактическое состояние расписания и уже назначенных пробуждений. Не доверяй только прежнему тексту в памяти. Проверяй отмены, переносы, часовой пояс и конкретные экземпляры повторяющихся событий. Если один календарь выбрал событие дважды, оставь одно пробуждение; при конфликте разных одновременных встреч уточни приоритет лишь когда без него нельзя безопасно выбрать.
2. На ближайший доступный период поставь **отдельное одноразовое** пробуждение за несколько минут до каждого подходящего экземпляра. Не ставь еженедельный повторяющийся будильник на лекцию. Ключ события составляй из источника, UID и конкретного начала в ISO 8601. В данные пробуждения запиши имя личного навыка, UID, начало и при наличии стабильную ссылку на карточку: по ним агент сможет вновь открыть календарь и получить актуальную ссылку на комнату. Сохрани возвращённые ID в `agent-state.json`.
3. Сверь новый список с прежним: добавь новые, переставь перенесённые, отмени отменённые, сохрани неизменные без дубликатов. Не удаляй действующие пробуждения при ошибке чтения календаря; зафиксируй сбой и назначь повторную попытку. Фраза «напомню» не заменяет реальный планировщик.
4. Отдельно назначь проверку календаря с выбранной в личном навыке частотой; **неделя — лишь запасной вариант**, когда пользователь не ответил. Время выбирай так, чтобы успеть подготовиться к ближайшим событиям. Запиши последнюю и следующую проверку, ID её пробуждения в `agent-state.json`. При каждом пробуждении проверяй, не просрочено ли обновление; если оно просрочено, восстанови проверку при первой возможности.

При близкой или уже идущей встрече сначала открой её и запусти запись по `auto-meets-capture`. Обновление календаря выполняй параллельно, если есть независимый исполнитель, либо сразу после запуска записи; оно не должно задержать лекцию. Перед входом быстро перепроверь событие и ссылку. Если источник недоступен, используй последнюю проверенную карточку только когда её актуальность можно подтвердить, а неопределённость сообщи пользователю.

Если выяснил устойчивую особенность календаря или обход проблемы, обнови **его** личный навык. Общий алгоритм остаётся здесь.
