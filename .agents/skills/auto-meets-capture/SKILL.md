# Подключение и запись

Используй навык перед встречей и во время её записи. Точные аргументы CLI и значения статусов смотри в `docs/USAGE.md`, проверку оборудования — в `docs/TESTING.md`. Прочитай указанный в пробуждении **личный навык календаря**: в нём источник, имя входа, предпочтения и проверенные обходы. Если в пробуждении нет имени, найди навык по UID/источнику события. Технические настройки записи лежат в `data/recorder.toml`. Проверь актуальность события и разрешение на запись.

Открывай ссылку на встречу прежде всего **в уже запущенном локальном Chrome/Edge**, которым можешь управлять через Browser Use: найди его существующую вкладку и перейди по ссылке в ней. Создание новой вкладки или окна инструментом Browser Use может открыть другой браузерный процесс, невидимый локальному рекордеру. Не вызывай `auto-meets browser` и не запускай отдельный профиль, пока доступен подходящий существующий браузер. Если пришлось создать новый, перед записью отдельно докажи, что Browser Use и `windows` видят одно и то же окно и его PID/HWND; при расхождении запись не начинай.

1. Открой календарь по ссылке из личного навыка, найди карточку нужного события и возьми **актуальную** ссылку на комнату. Для навигации по странице используй Browser Use: без управляемого браузера автоматическое подключение не подтверждено. Если есть Computer Use, **обязательно** используй его для проверки реального окна и для действий с Windows или выбором звука. Когда существующую сессию нельзя контролировать, попробуй доступный управляемый локальный браузер, сохранив изоляцию звука, и лишь при конкретном блокере обратись к пользователю. Проверь адрес, видимое содержимое, название встречи, вход/допуск и вывод звука. Используй выбранное пользователем имя из личного навыка. Не угадывай отсутствующую ссылку; проверь карточку и сообщения площадки. **Всегда выключай камеру и микрофон в интерфейсе конференции до входа и перепроверяй после входа.** Не обходи логин, CAPTCHA или допуск.
2. «Подключение», «Ожидание» и предпросмотр сами по себе не означают сбой: лекция может задержаться более чем на 10 минут. Оставь комнату открытой и перепроверяй через `schedule.check_minutes`, пока событие актуально. Не дублируй подключения и не повторяй вслепую клики. Начинай запись только после подтверждённого входа.
3. Не открывай посторонние вкладки в браузере встречи: захватывается звук дерева его процессов. В уже работающем браузере проверь, нет ли другого воспроизводимого аудио; если есть, приостанови его, когда это безопасно, либо не начинай запись, пока короткая проверка WAV не подтвердит чистый звук встречи. После загрузки найди окно через `windows`; используй PID **владельца HWND**, не PID процесса-обёртки. Сверь адрес и содержимое с этим окном, а не только заголовок. При неясном соответствии не выбирай первое окно по имени процесса. При необходимости задай область презентации.
4. После изменения браузера или звука коротко проверь запись разрешённого материала: кадр должен принадлежать нужному окну, WAV — содержать его речь и не содержать звук других приложений. Запусти `start --consent --settings data/recorder.toml` с проверенными PID, HWND, названием, `event_key` и подходящими `--kind`, `--detail`, `--instructions` из личного навыка. Сохрани путь сессии. Сразу проверь `status`: `recording`, рост `audio_seconds`, первый кадр и непустой звук при наличии речи. `starting` и размер WAV сами по себе успех не доказывают. При неверном кадре останови эту сессию и не используй её материалы для отчёта.
5. Назначай реальные пробуждения через `schedule.check_minutes`. Это интервал наблюдения за **текущей встречей**, не частота пересмотра календаря. На каждом сверяй интерфейс встречи и `status`. Запись ведёт отдельный процесс: не держи вызов агента открытым только ради ожидания. `frame_stale` при неизменном слайде может быть нормальным; проверь, менялась ли презентация. Сам код не понимает окончание встречи по смыслу.

Когда встреча закончилась, выполни `stop` и дождись фактического завершения по `status`; `processing` ещё не готовый результат. При отсутствии звука, `interrupted` или выходе браузера сначала сохрани материалы и сообщи проблему. Не переходи без разрешения к записи всего экрана, общего системного звука или другого процесса. Не закрывай пользовательские приложения по имени. При сбое используй `stop` для процессов этой сессии, затем `process` для повторной обработки сохранённого WAV; не удаляй lock-файлы. Если проблема может повториться, сохрани симптом, проверку и решение или следующий шаг в личном навыке календаря.
