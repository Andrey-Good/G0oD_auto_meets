# Архитектура

## 1. Основное решение

Это локальный инструмент внешнего агента, а не агентная платформа. Агент отвечает за смысл и взаимодействие с сайтами. Python отвечает за длительные механические операции. Новая площадка обычно требует изменения сценария агента, а не нового слоя кода.

```text
Расписание → внешний агент → отдельный локальный браузер встречи
                 │                     │ PID + HWND
                 │ start/status/stop   ▼
                 └──────────────→ worker → GStreamer
                                      │      ├─ непрерывный PCM в audio.wav
                                      │      └─ PNG + время GStreamer
                                      ├─ audio.py → whisper.cpp → transcript.json
                                      ├─ frames.py → frames/ + frames.json
                                      └─ report.py → черновик HTML + задание агенту

транскрипция + кадры → внешний агент → summary.json → render → готовый HTML
```

Три Python-зависимости: Pillow для изображений, Jinja2 для экранированного HTML, psutil для идентификации процессов. TOML, JSON, WAV-заголовок, команды и блокировки обслуживает стандартная библиотека. GStreamer и whisper.cpp — отдельные локальные программы.

## 2. Где искать код

| Файл | Ответственность и точки входа |
|---|---|
| `cli.py` | Разбирает команды и возвращает JSON. `execute`, `main`, автономная `demo`. |
| `worker.py` | `start` запускает отдельный Python; `run` управляет записью и обработкой; `stop` посылает запрос через файл. |
| `capture.py` | `pipeline` собирает аргументы; `Capture` читает сообщения GStreamer; `doctor` проверяет инструменты. |
| `platforms/windows.py` | HWND/PID, отдельный браузер, WASAPI/WGC, запрет автоматического сна. |
| `platforms/test.py` | Синтетический звук и изображение. Не обращается к экрану и микрофону. |
| `audio.py` | Сохранение/восстановление WAV, один ASR-процесс, кэш блоков, единая временная шкала текста. |
| `frames.py` | Сравнение уменьшенных кадров, уникальные изображения и времена повторных появлений. |
| `report.py` | Проверка ссылок на источники и актуальности пересказа, HTML и `AGENT_BRIEF.md`. |
| `config.py` | Значения по умолчанию, проверка TOML, разрешение путей относительно профиля. |
| `storage.py` | Атомарный JSON, блокировки ОС, PID + время создания, сведения о сессии. |

Читать всё подряд не нужно: для обычной работы агенту достаточно `AGENTS.md` и `docs/USAGE.md`. При проблеме сначала `status` и соответствующий лог, затем нужная строка таблицы.

## 3. Жизненный цикл и данные

Состояния: `starting → recording → processing → ready_for_summary`. Ошибки распознавания дают `needs_retry`; неисправность захвата, отсутствие аудио или иной сбой — `failed`. Это не утверждение, что пересказ уже написан. Наличие `summary.json` показывает `summary_present`, а валидность проверяет `render`.

Одна встреча — одна папка `data/<UTC-время>-<случайный-id>/`:

```text
session.json            исходный профиль, заголовок, event_key, PID/HWND
state.json              фаза, heartbeat, процессы, длительность, ошибки
launch.json             процесс запуска, включая короткую фазу до инициализации
asr-settings.json       фактически выбранные параметры последнего распознавания
asr-process.json        идентификатор текущего дочернего ASR-процесса
stop.request            просьба остановить запись
.process.lock           эксклюзивное право обрабатывать эту сессию
worker.log              журнал фонового Python
capture.log             GStreamer: сообщения, времена кадров, ошибки
asr.log                 диагностика whisper.cpp

audio.wav               исходная запись PCM: 16 кГц, mono, 16 бит
chunks/000000.json      результат/ошибка одного блока ASR и его сигнатура
transcript.json/.md     весь распознанный текст, стабильные id, временные метки
frames.json             уникальные слайды, id, время первого и повторных показов
frames/f000000.png      сохранённые полноразмерные кадры
spool/                  временные PNG и короткие WAV для ASR
summary.example.json    пустая схема с актуальным source_digest
summary.json            пересказ внешнего агента со ссылками на источники
AGENT_BRIEF.md          автоматически подготовленное задание на пересказ
report.html             самостоятельная страница с относительными ссылками
```

`session.json` — исходный снимок настроек, а не глобальная изменяемая конфигурация. Каждый результат ASR содержит сигнатуру аудио, параметров и файла модели. Успешный совпадающий блок повторно не распознаётся. Ошибки можно повторить; смена размера блока очищает только производные результаты, не оригинал. `source_digest` связывает пересказ с текущими текстом и кадрами: устаревший пересказ не выдаётся за новый.

`data/agent-state.json` — простая память внешнего агента: ближайшее событие, id его пробуждения, активная сессия и проверенные особенности среды. Сам Python этот файл не использует как расписание и не выполняет содержащийся в нём текст.

## 4. Почему запись не зависит от скорости модели

У GStreamer один непрерывный конвейер. Звук сразу дописывается на диск. В отдельном потоке Python работает очередь с **одним** вызовом whisper.cpp; следующий блок читается только когда предыдущий завершён. Очередь ожидания — уже записанные байты на диске, а не неограниченный список в памяти.

В WAV заранее записан 44-байтовый заголовок. GStreamer дописывает raw PCM (`append=true`), после остановки Python исправляет длину заголовка. Поэтому остановка Windows-процесса не требует финализации сложного контейнера. После аварии `stop`, затем `process` восстанавливают заголовок из фактически сохранённого размера. Во время записи WAV-заголовок ещё не окончательный: проигрывать и экспортировать запись следует после остановки.

Времена текста считаются по числу аудиосэмплов. Времена изображений берутся из `running-time` сообщений `GstMultiFileSink`, а не вычисляются по номеру кадра. Живой источник тишины поддерживает непрерывный аудиотаймлайн, когда браузер не выдаёт звук. Исходная запись занимает примерно 110 МиБ в час, плюс PNG и один временный ASR-блок.

В первой версии блоки речи не перекрываются. Это проще и не добавляет эвристического склеивания слов; потерю контекста на границе нельзя считать решённой. Для важной речи можно увеличить `chunk_seconds`, повторить обработку и проверить исходное аудио.

## 5. Ограничение побочных эффектов

Подпроцессы запускаются без shell. Строковые свойства дополнительно экранируются для парсера GStreamer. Остановка касается только сохранённого PID с совпадающим временем создания; для осиротевшего процесса дополнительно проверяется аргумент с каталогом этой встречи. Нет `taskkill` по имени браузера и нет завершения чужих приложений.

Блокировки `.start.lock`, `.capture.lock` и `.process.lock` удерживает ОС; после аварии они освобождаются. Файлы блокировок не удаляются: удаление создаёт гонку между разными файловыми дескрипторами. Повторный `event_key` возвращает уже существующую сессию. Новая попытка записи после обрыва получает новый ключ/суффикс и отдельную временную шкалу; автоматически дописывать другую встречу в старое аудио нельзя.

Минимальный свободный объём и максимальная длительность ограничивают запись. Потеря целевого окна или остановка аудиопотока отмечается как ошибка, уже сохранённое аудио остаётся. Застывшие кадры видны в `frame_stale`. HTML экранирует текст, разрешает только локальные пути кадров, не загружает внешние библиотеки. Это проверка структуры и безопасности отображения, не доказательство правдивости пересказа.

## 6. Расширение без перестройки проекта

**Другая ОС:** добавить `platforms/linux.py` или `macos.py` с `ELEMENTS`, `preflight(profile, target)`, `sources(profile, target)` и контекстом `awake()`. Зарегистрировать имя в `platforms/__init__.py` и `config.py`. `sources` возвращает список источников аудио и источник видео; общий конвейер добавляет преобразования и приёмники. Оконные утилиты/запуск браузера — тоже часть адаптера; добавить их маршрут в CLI при реализации новой ОС. Проверить права, изоляцию приложения, временную шкалу и остановку. Формат сессий, ASR и отчёт менять не нужно.

**Другая площадка:** сначала изменить сценарий агента, работающего через локальный интерфейс. Создавать отдельный браузерный адаптер только при появлении повторяемой необходимости. Сейчас в коде нет селекторов BBB/Zoom/Meet и утверждения об их проверенной совместимости.

**Другой распознаватель:** заменить вызов в `transcribe_chunk`, сохранив результат с `id`, `start_ms`, `end_ms`, `text`, `uncertain`. Сигнатура кэша должна учитывать его настройки. Не добавлять облачную отправку скрыто.

**Другое оформление:** менять `templates/report.html`. Данные отчёта не должны содержать исполняемый HTML, пути наружу или JavaScript.

Фреймворк плагинов, база, REST API, внутренний календарь и диспетчер моделей не нужны, пока нет задачи, которую существующее разделение действительно не решает.

## 7. Первичные технические источники

- [WASAPI2: include-process-tree и loopback-target-pid](https://gstreamer.freedesktop.org/documentation/wasapi2/wasapi2src.html).
- [WGC: window-handle, capture-api и crop](https://gstreamer.freedesktop.org/documentation/d3d11/d3d11screencapturesrc.html).
- [Сообщения multifilesink и их временные поля](https://gstreamer.freedesktop.org/documentation/multifile/multifilesink.html).
- [Непрерывный живой audiomixer](https://gstreamer.freedesktop.org/documentation/audio/gstaudioaggregator.html).
- [filesink: append и buffer-mode](https://gstreamer.freedesktop.org/documentation/coreelements/filesink.html).
- [whisper.cpp: код CLI и формат JSON](https://github.com/ggml-org/whisper.cpp/blob/master/examples/cli/cli.cpp).

`gst-launch` выбран как заменяемый командный адаптер ради простой установки без Python/GI. Разработчики GStreamer рекомендуют [нативный API для полноценных приложений](https://gstreamer.freedesktop.org/documentation/tools/gst-launch.html). Здесь цена упрощения — зависимость разбора сообщений от CLI; она ограничена `capture.py`, покрыта тестом и проверяется при смене сборки. При появлении необходимости этот модуль можно заменить вызовами API без перестройки остального проекта.
